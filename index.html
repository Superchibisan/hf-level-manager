HF Leveling Level Manager — Rev 3, Low-Latency Redesign

Date Oct 26, 2026
Author @Vincent
Version Rev 3 · corrected Oct 27, 2026
⚑ Corrected by design review — Oct 27, 2026. Changes marked throughout.

Summary

Rev 3 is a multi-stage level manager with HF leveling, rebuilt so the audio path adds effectively zero latency in its analog build and only a few samples in its digital build. It keeps every function from rev 2's management stages and drops everything that made audio wait.

What it does, per linked channel group:

  • Leveler: rides overall gain on loudness averaged over minutes.
  • Overdrive limiter: catches short overshoots and hands sustained ones back to the leveler.
  • LF ceiling: caps content below 100 Hz.
  • HF leveling (new): holds treble to a consistent ratio of overall loudness and below an absolute ceiling.

What changed from rev 2:

  • Lookahead removed, saving 2 ms.
  • Band split made complementary, so the output equals the input exactly when nothing is acting.
  • Scope cut to an insert. Crossover, zone EQ and driver protection stay in the downstream system processor.
  • Audio stays in its native domain: an analog VCA path for analog systems, a synchronous AES3 path for digital ones. No converters or sample rate converters are added to the audio path.
  • All analysis moved to a parallel sidechain, where delay does not reach the audio.
Correction — latency claim "Effectively zero latency in the analog build" is an architectural assertion, not a measured figure. The VCA control signal is derived from sidechain analysis; it carries filter settling time, detection time-constant delay, and DSP pipeline delay even in sample-by-sample mode. The claim must be confirmed by impulse measurement on the prototype. Until then this spec uses architecturally zero added latency in the audio path and defers the measured figure to validation.

Design Principles

Seven rules, each removing a source of delay or a reason to add one.

  1. Nothing in the audio path waits. No lookahead, no FIR filters, no block buffers. The slow stages work on minutes of history and need no lookahead. The fast overdrive stage accepts a brief overshoot, which the downstream protection limiters catch.
  2. The audio path only multiplies. Gain is applied to the full signal and to two derived bands. Every measurement happens in a parallel sidechain.
  3. Complementary bands. LF is a lowpass of the input, HF is the input minus a lowpass, and mid is whatever remains. The three always sum back to the input, so with all gains at unity the output equals the input in level and phase.
  4. Stay in the native domain. Analog systems get an analog path; digital systems get a digital path. The device never converts audio just to process it.
  5. Synchronous clocking. The digital build locks to the house clock with sample rate conversion switched off.
  6. Sample-by-sample processing. The sidechain DSP processes each sample as it arrives rather than in blocks.
  7. Fail-safe bypass. A hard-wired relay connects input to output whenever power is lost, the DSP stops responding, or audio is present at the input but missing at the output. A hardware clamp on the VCA control voltage limits attenuation to a fixed floor (proposed −20 dB), so no control fault can silence the system.
Correction — sidechain latency Principle 2 states that every measurement happens in the parallel sidechain. This is correct; the audio path carries no analysis delay. However: the VCA gain elements respond to a control signal derived from sidechain analysis. That control signal has real latency — filter settling time, detection time constants (attack and release time constants of each stage), and DSP pipeline delay. In the analog build this latency affects how quickly each stage responds to a transient, not the audio path phase or level at idle. The overdrive stage's response time to a fast transient is the principal consequence; the spec's treatment of this as acceptable (downstream limiters catch what slips past) stands, but must be quantified on the prototype.

The band structure, with g the broadband gain:

M = x − L − H, y = g·(M + g_LF·L + g_HF·H)

Here L is a lowpass of x at 100 Hz and H is x minus a lowpass at the HF corner. With every gain at 1, y equals x exactly.

Architecture

The audio path is a band split, three gains and a sum. Everything that measures or decides runs beside it.

Accented blocks are the gain elements: VCAs in the analog build, multiplies in the digital build. The bypass relay passes audio untouched if power fails, the DSP stops, or audio goes missing at the output.

Correction — cascade interaction Five stages sharing three gain elements with different time constants (minutes-scale leveler, fast overdrive limiter, fast HF overdrive, slow HF leveler, fast LF ceiling) is a known design challenge. Simultaneous action by stages operating at different speeds can produce interaction artifacts: gain pumping, transient over-compression, or oscillation between stages when all act on the same program material. The original spec does not address this. Validation must include multi-stage interaction testing (see Validation section). Simulation or measured transfer functions for typical program scenarios should be completed before production commit.

Leveler Target Level Specification — added

Added — specification gap closed The K-weighted Leveler had no target reference level defined in the original spec. This section closes that gap.

The Leveler is a closed-loop controller. It requires a defined setpoint to be specified, tuned, and validated. Without one, the stage cannot be tested against a pass/fail criterion.

Proposed reference

The Leveler's target is the Max loudness control setting, expressed in the same K-weighted units as its detector. The detector uses the K-weighting of ITU-R BS.1770 (a high-shelf boost plus a high-pass). The Max loudness control should therefore be calibrated in loudness units relative to full scale (LUFS) on a K-weighted integrated scale, matching the detector's own measurement.

Proposed default: −16 LUFS-K integrated over the leveler's averaging window, with the tamper-proof maximum set at −12 LUFS-K. These figures are starting points for testing; actual values are determined by listening tests and operator feedback.

Open item Live PA has no equivalent of broadcast's EBU R128 standard. The proposed figure is a practical starting point, not a regulatory reference. The Learn function (which sets the target to the current loudness of show material) means the absolute value is operator-chosen, but the units must be consistent with the detector's measurement scale. Confirm units and proposed defaults in prototype listening tests before publishing any specification value.

HF leveler ratio

The HF leveler's "Brightness" control sets the allowed ratio of HF-band loudness to overall loudness. This ratio also requires a specified range and default. Proposed default: −6 dB HF relative to overall K-weighted loudness (i.e. treble may not exceed overall by more than 6 dB once the leveler acts). Set in testing.

The shared rules from the original spec remain:

  • Gains are linked across every channel in a group.
  • Attenuate only. No stage ever raises gain above unity.
  • Gain changes are slew-limited to avoid zipper noise and modulation.
  • The SPL loop only trims the leveler and HF ceiling targets slowly, within a capped range.

Added — DSP load prerequisite Before committing to the ADAU1467 and board layout, complete prerequisite P-4: verify that the processor can sustain all five control algorithms simultaneously at sample rate without DSP load overflow. If the load exceeds the processor's capacity, the architecture requires either a second DSP, algorithm restructuring, or a more capable processor. This is a desk calculation that should precede board design.

Why these parts:

  • THAT2180: exponential (dB) gain control, under 0.01% distortion in the A grade, over 120 dB dynamic range, and a ±15 V supply that matches the analog rails.
  • ADAU1467: a 294.912 MHz core with I/O up to 192 kHz and support for sample-by-sample stream processing.

If the digital build needs analog I/O as an option, use converters with minimum-phase filters. The AK4458 DAC has short-delay filters with a group delay of 5.8 or 4.8 samples, about 60 µs or 50 µs at 96 kHz. A matching short-delay ADC is still to be selected; the PCM4202 shows mixed lifecycle status at distributors.

Analog build specifics

  • Analog idle null. How exactly the bands sum to the input depends on component matching. Use 0.1% resistors and a trim, and measure the null.
  • Analog filters are fixed or switched, so HF corner choices are fewer than in DSP.
  • VCA noise and distortion are low but not zero; the THAT2180A grade specifies under 0.01%.

Measurement Mic

The mic is optional. Every core stage works on the audio signal alone; the mic adds settings in real dB SPL, compliance metering and logging, and the slow trim near a legal limit.

Rear-panel input. One XLR on the back panel, feeding a THAT1512 preamp and then the sidechain ADC only. The mic never reaches the audio path.

  • Phantom power to IEC 61938 P48: 48 V through 6.81 kΩ feed resistors on pins 2 and 3, matched to 0.1% or better, up to 10 mA. Soft-start, switchable, front-panel indicator.
  • Input protection with blocking capacitors and clamp diodes.
  • Mic correction file loaded in the app.
Added — SPL log liability Compliance SPL logs are presented as a compliance feature and a potential revenue platform. Before marketing them as compliance evidence, establish what liability exposure exists if logs are used in regulatory or legal proceedings and contain errors (timing gaps, calibration drift, instrument uncertainty). Pursue IEC 61672 Class 1 or 2 certification for the measurement chain or document clearly that the device is a monitoring aid, not a certified measurement instrument. This affects how the feature is marketed and what claims the app makes about log accuracy.

Three measurement modes: Live mic (continuous), Calibrated estimate (measured once at setup, then signal-derived), No mic (signal units only, compliance features off). If the mic drops out mid-show, the device keeps running on signal-based thresholds and holds the last SPL trim; the app shows a warning and the compliance log marks the gap.

A 2.4-inch transflective color TFT on SPI. An ambient light sensor sets the backlight and LED ring brightness automatically.

Presets

  • Switching is seamless. Gains glide to new targets at the normal slew rate; the leveler keeps its current state instead of resetting.
  • Power-up returns to the last-used preset, in bypass until the DSP is running.
  • Edited indicator. A preset button blinks when any value differs from the stored version.
  • Hidden maximum. The tamper-proof threshold applies across all presets.
  • Templates for speech, live band and DJ shows; values set in testing.

Validation and Open Questions

No latency or tuning figure in this spec is proven until these tests run on a prototype. Prerequisites P-1 through P-6 must complete before the prototype is ordered.

Prototype validation tests

  • End-to-end latency — impulse in to impulse out, for both builds (replaces "effectively zero" and "a few samples" with measured figures)
  • Idle null — output minus input with every gain at unity, across the audio band
  • Overshoot — tone bursts above the overdrive threshold; record peak overshoot and duration
  • HF band shape — measure how far HF reduction reaches below the HF corner
  • Cascade interaction — program material that simultaneously triggers leveler, overdrive, and HF stages; measure for pumping or gain hunting
  • Listening tests — leveler and HF leveler assertiveness settings on real show material
  • VCA control latency — measure time from a transient at the sidechain ADC input to gain change at the VCA output
